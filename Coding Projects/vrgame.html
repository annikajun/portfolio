VR Game


For this assignment (CS4071 Virtual and Augmented Reality Design), I designed and built a first-person VR Maze Adventure game set in a fictional fantasy world called the Labyrinth of Nexos. The player is transported into Nexos and must solve a series of mazes to escape. The game was built in Unity using the XR Interaction Toolkit and targets the Meta Quest 2 headset.

Game Overview


The game is split into four scenes: a main menu, Level 1, Level 2, and an exit menu. The main menu welcomes the player to the Labyrinth of Nexos and gives them the choice to play or quit. Level 1 is a simpler maze with two types of help items, an aerial view and directional signs, to ease the player in. At the end of each level, a portal transports the player to the next scene. Level 2 features a more complex layout with fewer help items, providing a greater challenge. The exit menu lets the player start a new game or quit.

The player explores the world through a VR headset and two controllers. Controllers enable movement and interaction with game objects. The target demographic is hobby gamers and anyone who enjoys VR adventure games and fast-paced problem-solving.

Development Process


The game was built using Unity's XR Interaction Toolkit with an Oculus configuration, targeting the Meta Quest 2. The XR Origin Set Up Variant Prefab provides the headset-tracked camera and controller models. Player movement uses a Locomotion System with a 45-degree snap turn, the industry standard for VR comfort, and a move speed of 10 with standard gravity for a natural feel. A Character Controller component prevents the player from walking through walls and handles trigger collisions with interactive elements like tooltips and portals.

Testing was a key part of the process. I initially planned to use Meta Link for real-time testing, but discovered it required Windows and a GPU, neither of which I had. Instead, I side-loaded the APK onto the Quest 2 via Sidequest, allowing for direct hardware testing. During development, the XR Device Simulator was used to translate keyboard and mouse inputs into simulated VR controller actions, enabling rapid iteration without exporting a full build each time.


In-game view of the maze environment


World Building & Assets


The maze walls were created using scaled cubes with textures from Phoenix3D Studio's Outdoor Wall Tile Texture Pack. The maze floor layouts were generated from imported JPEG images linked to each plane's Base Map shader. Two distinct layouts were used across the levels, with the second being more complex and including more dead ends to increase difficulty.

A fantasy skybox and atmospheric fog were added to immerse the player. Medieval ambient audio tracks play in each level, and a sparrow companion, triggered when the player enters its collider, flies ahead to guide them through the maze. Noticeboards at the start of each level provide storytelling context, and a Do Not Enter sign was used as directional signage. Portals with animated effects connect the scenes and transport the player between levels.


Menus & UI


All menus, the main menu, in-game pause menu, and exit menu, were built using Unity UI Canvases in World Space mode, attached to the XR Origin VR Player prefab so they remain in view at all times. The in-game menu is toggled with the left Meta button on the controller and offers Pause, Resume, Restart, and Quit options. Players interact with buttons by hovering their controller ray over them; the ray turns blue to indicate a selectable element, providing clear visual feedback. The main menu presents the Labyrinth of Nexos theme with "Bravery" (play) and "Cowardness" (quit) as the player's choices.

Reflection


Overall, I am pleased with how the project turned out. The game's navigation and narration structure worked effectively, and the materials, sounds, and environmental effects suited the fantasy setting well. That said, there are a few things I would approach differently. Because tiling is unified across all materials, scaling the maze walls caused some texture distortion. I also had to reduce the terrain's grass and tree loading distance to prevent lag that could have caused motion sickness, a necessary compromise but one that affected the richness of the world.


I also wish I had made greater use of Unity prefabs from the start. Many elements were copied and pasted across scenes, which would have been much more efficient had they been organised as prefabs originally. If I were to build this game again, I would invest more time creating an immersive world and incorporate more interactive maze elements, such as objects that move, break walls, or react to the player, to make the experience even more dynamic.
